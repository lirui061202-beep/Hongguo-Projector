# 界面改版：极光 TV 式排版与设计令牌

> **本文件的色板与形状语言已被新拟态改版取代**，见 [新拟态界面改版说明](UI_NEUMORPHISM.md)。
> 仍然有效的是这里的**排版结构**（顶部频道导航、分区横向剧架、海报卡、选集网格）、
> **焦点与裁剪规则**、**按钮规范**与**页头随滚动收起**——本轮只换了材质，
> 下面提到的 `#1B1B20` / `#1E1E21` / 6dp 圆角 / 「焦点统一白底 + 深字」都请以新文件为准。

本轮把原生版的界面按「腾讯视频极光 TV」的排版逻辑重做了一遍：近黑沉浸底色、顶部频道导航、
分区横向剧架、圆角海报与统一的焦点反馈。改动集中在 UI 层，内容协议、签名、播放与解密代码未动。

## 参考的排版结构

| 位置 | 极光 TV 的做法 | 本项目的实现 |
| --- | --- | --- |
| 顶部 | 左侧品牌，右侧辅助入口 | 品牌按钮（回首页）+ 右侧 48dp 圆形图标入口：搜索 / 排行榜 / 设置 |
| 内容区 | 分区标题 + 横向海报架，逐行向下滚动 | `HomeScreen`：`SectionHeading` + `HorizontalScrollView`，行内横向记忆位置 |
| 首页首行 | 大卡推荐位 | `PosterCard` 的竖版海报架：一屏 6 张、行内 14dp 间距，剧名与状态放在卡下 |
| 海报卡 | 圆角竖版海报，焦点放大并描边 | `PosterCard`：7:10 圆角封面 + 左上角标 + 卡下剧名/状态 + 底部进度 |
| 详情页 | 海报 + 信息 + 胶囊主按钮 + 集数网格 | `showDetail()`：完整竖版海报（左）+ 标题 / 简介 / 胶囊主次操作（右）+ `EpisodeGrid` 集数网格 |
| 选集 | 底部抽屉，一页 20 集 | `EpisodeGrid`：简介页与播放界面共用同一份网格，10 列 × 2 行圆角单元格 |
| 播放器 | 上键弹设置、下键弹选集 | `PlaybackMenu`：右侧竖向面板，清晰度 / 倍速 / 画面模式 / 定时 四项，选项等分并自动换行 |

**没有做全屏大图轮播**：接口只提供约 7:10 的竖版封面，拉伸成 16:9 会明显变形；
按 `CENTER_CROP` 铺满又只剩中间一条，且要多缓存一张全屏位图。低配电视的内存预算不支持这个取舍，
因此推荐位改用「3 列横卡 + 浮层」表达同一层级。

同一条理由也决定了详情页的排版：早期版本把封面 `CENTER_CROP` 成整幅通栏剧照、标题压在图上，
结果封面只剩中间一条，文字还要靠一层半透明渐变撑可读性。现在改为**海报完整显示 + 信息右置**：
海报按接口原始比例（约 7:10）`FIT_CENTER` 整张放进圆角卡座，高度取屏高的 48%（上限 430dp），
标题、集数题材、简介与主次按钮排在右侧的纯色页面上，因此不需要压暗层、模糊层或文字投影。

## 焦点与裁剪

焦点缩放会被父容器裁掉，这是电视端最容易踩的坑。规则如下，改动布局时必须保持：

1. **行 / 列容器一律 `clipChildren = false`**（`TvComponents.tvRow()/tvColumn()` 与
   `MainActivity.row()/column()` 已经默认带上）。中间任何一层行 / 列一旦裁剪，
   贴在它边缘的那张卡片 / 那个按钮的焦点反馈就会被切平。
2. **裁剪边界取的是「直接父级」的 `clipChildren`，不是控件自己的**。框架里写死了：

   ```java
   // View.setDisplayListProperties()
   renderNode.setClipToBounds(mParent instanceof ViewGroup
           && ((ViewGroup) mParent).getClipChildren());
   // 软件绘制路径同样只看 parentFlags & FLAG_CLIP_CHILDREN
   ```

   于是同一条需求必须拆成两处来做，缺一不可：

   - **滚动容器自己 `clipChildren = false`**（`ScrollView.focusBleed()`）。这个开关管的是
     「子控件会不会被裁到子控件自己的边界上」；打开它等于把列表裁在列表自己的边界上——
     列表本来就有整份内容那么高，裁了等于没裁，却正好把第一行 / 最左边那张卡放大后
     画到列表边界之外的那条描边切掉，观感就是「最左边的选中框只剩一半、上边框看不见」。
   - **滚动容器的直接父级 `clipChildren = true`**（`TvComponents.tvScrollHost()`）。
     把滚动内容关在可视区里的那道裁剪只能由父级提供；父级不裁，上滚的卡片就会画到
     滚动容器之外，盖住页头那一排按钮（页头是透明底，观感就是「按钮跑到列表后面，很乱」）。
     外壳里只放滚动容器一个子控件，因此打开裁剪不会碰到任何按钮的焦点放大。

   余量仍然做在容器**内部**：`focusBleed()` 四边都留内边距——左右 `FOCUS_BLEED`（7dp），
   上下 `FOCUS_BLEED_VERTICAL`（12dp，海报卡是竖的，向上溢出更多）。
   1.05 倍放大让控件画出自身 2.5%：175dp 宽的海报卡横向 4.4dp，
   288dp 高的竖版卡纵向 7.2dp，4K 画布上约 11.3dp。
   `clipToPadding = false` 保证不额外裁到内边距框，这 7dp / 12dp 才真的可用。
   页面容器因此比内容线早 7dp 开始（`pageBleed()`），滚动容器再补回来，内容仍然精确落在
   78dp 栅格上；工具栏、页头、搜索行等非滚动内容各自补回这 7dp，保持同一条内容线。
3. 边界本来就是整屏宽的滚动容器（简介页整页滚动、播放器 HUD）不需要余量，
   在源码里用 `focus-bleed-exempt` 注明，`tools/verify-button-system.py` 会按这个标记核对；
   高度是 `WRAP_CONTENT`、内容永远不超过自己的滚动容器同样不需要外壳。
4. 圆角用 `clipToOutline` + `ViewOutlineProvider` 裁剪，而不是叠加遮罩位图：
   不额外分配内存，缩放后边缘依然锐利。

> 反面教材：改版前 `HomeScreen` 的剧架把第一张卡片放在滚动容器左边界上，
> 放大后左侧描边落在边界外 2.4dp，于是**整条左边框消失**（右侧因为内容更宽、可以滚动，反而看得见）。
> 详情页的「继续观看」按钮左侧同样被 `actions` 行裁成平直切口，可以在
> `captures/episode-grid/detail-page-new-layout.png` 里量出来。
>
> 另一条反面教材（2026-10-06 修）：为了补上面这条，曾经把滚动容器的 `clipChildren` 关掉，
> 结果列表不再裁剪——向上滚动时卡片画到了页头那一排按钮上面，页头是透明底，
> 观感就是「红果TV / 漫剧 短剧 / 搜索 排行榜 设置 跑到列表后面，很乱」。
> 随后改成「容器自己打开裁剪」，描边又被切回来了：**控件自己的 `clipChildren` 根本管不到
> 自己的裁剪**，它管的是子控件的裁剪。真正的分界线是「容器留余量、外壳做裁剪」（第 2 条），
> 两件事不能互相替代，`tools/verify-button-system.py` 第 9 条按这个规则核对。

## 组件清单（`TvComponents.kt`）

- `TvButton`：**全站唯一的按钮实现**，尺寸走 `ButtonSize`（40 / 48 / 56dp 三档）、
  外观走 `ButtonTone`（主操作 / 常规 / 文字），焦点反馈与间距由组件自己负责。
- `IconButton`：顶部导航的圆形图标入口（刷新 / 搜索 / 排行榜 / 设置），48dp 圆、24dp 图标，
  当前页用强调色填充；刷新排在「搜索」左边，刷新对象是当前这一页。
- `ToggleChip`：短剧 / 漫剧互斥开关，就是 `TvButton` 的选中态。
- `PosterCard`：首页架子与列表页共用的竖版海报卡（`bind()` 负责角标、状态与进度）。
- `SectionHeading`：粗体标题（可带灰字副标题），从内容线开始。
  2026-10-12 起标题前不再有强调色圆点，也不挂「更多 ›」。
  2026-10-12 起标题行不再挂「更多 ›」：剧架行末的「查看全部」底板就是入口。
- `EpisodeCell`：选集网格单元——网格方块保留 6dp 圆角，但高度、字号、焦点反馈与按钮同源。
- `TvDialog`（`TvDialog.kt`）：**全站唯一的模态框**，标题 + 内容 + 一排 `TvButton`，
  列表型弹窗每项都是整行左对齐的常规按钮；应用里不再有系统 `AlertDialog` 的 Material 文字按钮。
- `EpisodeGrid`（`EpisodeGrid.kt`）：简介页与播放界面共用的选集网格——标题行、集数行、
  10 列 × 2 行 48dp 单元格、8dp 间距、渐变背板与四向翻页只有一份实现，宿主只决定高度。

## 按钮规范（2026-10-06 统一）

改版后按钮的观感问题集中在三件事：同一个界面里按钮高度不一（38 / 42 / 44 / 48dp 混用）、
内边距与字号各写各的（32/9、32/14、22/8、20/14 四种）、间距靠调用方手写 `rightMargin`，
于是行尾多出 8dp、两个按钮贴在一起这类问题反复出现。现在收敛成一套规则：

| 维度 | 规则 |
| --- | --- |
| 高度 | 只有三档：紧凑 40dp（菜单选项、行内文字入口）、常规 48dp（返回 / 分页 / 重试 / 收藏 / 设置项）、主操作 56dp（详情页唯一强调按钮） |
| 横向内边距 | 跟着档位走：18 / 28 / 36dp，不再由调用方给 |
| 字号 | 15 / 16 / 17sp 粗体，与档位绑定 |
| 圆角 | 一律胶囊 24dp（`RADIUS_PILL`）；选集网格方块与海报卡片保留 6dp |
| 外观 | 只有三种语义：`PRIMARY` 强调色填充、`SECONDARY` 12% 白填充 + 18% 白描边、`GHOST` 无底文字；选中态统一强调色填充 |
| 焦点 | 统一白底 + 深字 + 放大 1.05，不再有 1.04 / 1.06 / 1.08 的差别 |
| 禁用 | 统一 40% 透明度 + 30% 白字 |
| 间距 | `GAP_INLINE` 12dp（同一行按钮）、`GAP_TIGHT` 8dp（网格）、`GAP_BLOCK` 16dp（区块）、`GAP_GROUP` 24dp（大分组）；由 `addButton` / `gapInto` 统一施加 |
| 最小宽度 | 92dp（文字按钮除外），「收藏」这类短文案不会瘦成一条 |

落地位置：`TvStyle.kt` 存令牌，`TvComponents.kt` 存唯一的 `TvButton` 与绘制函数 `paintButton()`，
`TvDialog.kt` 存唯一的模态框，其余文件只调用。播放器底部的状态行（清晰度 / 倍速 / 画面模式 / 定时）
仍是纯文字入口——它在画面上方、不抢焦点，保留 20sp 的播放器排版，不进按钮族。

防止回退：`tools/verify-button-system.py` 静态校验上述规则（唯一实现、三档高度、令牌化内边距、
焦点缩放唯一、弹窗统一、胶囊底色只用令牌），改动绕过 `TvButton` 会直接失败。
它是源码级护栏，不替代真机验收。

## 选集

简介页的选集不再自己写一套网格，也不再是「上一组 / 下一组 / 跳转集数」按钮行：
页面末尾直接贴一块 `EpisodeGrid`，与播放界面按「下键」弹出的面板长得完全一样——
同样一行「选集 + 正在看第 X 集 · 共 N 集」、同样一行「第 X—Y 集」、同样 10 列 2 行单元格。

- 播放界面：`EpisodePanel` 只是把同一个网格放进贴底、整宽、约 300dp 高的透明弹窗。
- 简介页：网格整幅贴在页面末尾。两处宿主不同，翻页方式完全相同。
- 一页 20 集，四向都是「到边缘再翻页」：左右到本行两端翻相邻页，第一行按上翻回上一页，
  最后一行（或本页只有一行时）按下翻到下一页；只有确认单元格才换集，翻页只移动焦点。
- **没有目标页时按键交回焦点系统**（`EpisodeGrid.turn()` 越界返回 `false`）：
  播放面板里没有上一页 / 下一页时焦点停在原地；简介页第一页第一行按上就离开选集，
  回到「继续观看 / 收藏 / 完整简介」这一行——详情页不留页头，这是它唯一的向上出口，
  所以这条返回 `false` 的越界判断不能改成「吃掉按键」，否则选集在简介页会变成焦点孤岛。
- 两处都不再有「跳转集数」键盘，选中集数的路径统一为「翻页 → 确认」。

`MainActivity.button()` / `addButton()` 只是 `TvButton` 的薄封装：按钮高度、内边距、圆角、
焦点反馈都来自组件，页面只负责文案、语义与点击。间距也只有一个来源——横向容器加左边距、
纵向容器加上边距，第一个子控件不留边距，因此不会出现「两个按钮贴在一起」或「行尾多出 8dp 把整行推偏」。

## 返回键

- 播放界面：先收浮层（设置菜单 / 控制条），再回简介页。
- 简介页：回列表。
- 集合页：回首页并恢复原焦点。
- 首页：焦点不在顶部导航时，先回到导航；**导航上再按返回弹出确认框**（`confirmExit()`），
  确认才 `finish()`，取消则焦点留在导航上。弹窗走全站统一的 `TvDialog`，
  焦点默认落在「取消」，误按返回不会退出应用。

## 播放器菜单

播放界面去掉了旧的一行文字操作（播放 / 上一集 / 下一集 / 选集 / 播放设置），改成两个方向键各管一件事：

- **上键**（或菜单键）打开 `PlaybackMenu`：右侧竖向面板，自上而下是「清晰度 / 倍速 / 画面模式 / 定时」，
  每项的选项等分排在项目名右侧，定时 8 个选项按每行 4 个换行。
- 上下换项目（含换行），左右换选项，确认立即生效，返回收起整个浮层；四向都锁在菜单内部，
  停在最后一行（定时）再按下键焦点留在原地，**不会跳进选集**——菜单是「上键」打开的浮层，
  在它里面按到边缘只表示到头了，换界面仍然只由菜单关闭后的下键 / 底部下拉箭头负责。
- **下键**仍是 `EpisodePanel`，底部居中的下拉箭头保留，作为触控 / 鼠标入口。
- 播放与暂停回到画面中央的确认键和底部播放键图标；上一集 / 下一集保留在媒体按键与选集中。
- 底部状态行（清晰度 / 倍速 / 画面模式 / 定时）只显示当前值，点击可直接打开菜单的对应项目。

菜单只做原生 View，没有新增位图；选项选中态用品牌色填充，焦点态沿用白底深字，与全站按钮同一种手感。

## 首页剧架与远端长列表

- 顶部导航只有品牌、搜索、排行榜、设置四个入口（`nav` 4 项：`switchTab(0..3)`，设置从原来的第 5 位挪到第 3 位）。
  收藏和观看记录不再占导航位，改为首页剧架；原来的两个页面里「检查更新」「管理记录」按钮分别跟着
  收藏集合页、观看记录集合页的页头。
- 首页剧架按「历史记录 → 我的收藏 → 热门推荐 → 热门发现」排列，用户加过稍后看内容时稍后看作为
  最后一栏出现。每栏最多十部（`take(10)`），超过十部才在行末挂「查看全部」。来自本机记录的
  历史记录、我的收藏、稍后看没有数据时 `HomeScreen.render()` 直接不渲染这一行，因此不会留空位。
  历史记录按最近观看排序，未看完的条目确认后直接续播，整剧看完的条目只显示状态；
  我的收藏沿用 `Library.favoriteLabel()`（「新增 N 集 · 更新至 M 集」），所以收藏更新信息没有丢。
- 首页「热门推荐」固定十部（`MainActivity.homeShelves()` 里的 `hot.take(10)`），
  第 11 部起顺延到「热门发现」（`hot.drop(10).take(10)`），两个分区不重复。热门发现的标题只写
  「热门发现」，不拼片库分类（分类在页头开关上，标题里再写是重复的）。首页只缓存一页，
  所以只要远端还有下一页，两个分区行末都留「查看全部」，按右键即可进入热门集合页。
- 两个热门剧架共用同一份热门列表，所以集合页标题由进入它的剧架决定（`showCollection(kind,title)` →
  `collectionTitle`）：从热门推荐进就是「热门推荐」，从热门发现进就是「热门发现」。
- 2026-10-12 起首页底部不再有「更多热门」入口（整条底部按钮行一起去掉）：热门内容在首页就是
  热门推荐 / 热门发现两个剧架，行末「查看全部」已经能把整份热门接下去看。热门集合页本身
  仍是向下追加，只有「展示更多 ↓」，没有页码按钮。

  （首页取热门第 1 页、搜索重跑当前关键词、榜单重取第 1 页、本机记录页重读本机索引、设置页给提示）。
- 远端长列表（热播榜 `tab==2`，以及集合页 `collection=="hot"`，由 `appendCatalog()` 判定）
  不再有「上一页 / 下一页 / 下一批热门」，也没有页码文字：`catalog` 就是向下追加出来的整份内容，
  一次全部画出来。底部一行左边是已显示进度，右边是「展示更多 ↓」按钮
  （`LOAD_MORE`，与全站按钮同一套 `TvButton` 常规档样式）。
- 最后一行按下键落到该按钮，再按确认或下键加载下一页：新一页只接住没出现过的剧集，
  名次与热度按页合并（`mergeRanking`），焦点落到新增的第一张卡片，滚动位置沿用同一把 key
  （远端长列表的 `catalogPageKey` 不带页码）因此不会跳回顶部。
- 进度文案：榜单自带总页数，显示「已显示 20 / 100 部」；首页热门只知道追加到第几页，
  显示「已显示 20 部」，到末页统一变成「已显示全部 N 部」。
- 追加失败不动已经显示的内容，页码退回待加载的那一页，按钮留在原处可以直接重试。
- 收藏、接着看、稍后看、收藏有更新这些本机列表，以及搜索，仍然按页切换，不受影响。

## 页头随滚动收起（2026-10-06）

列表向下浏览时，页头那一整块（工具条上的品牌「红果TV」、漫剧 / 短剧分类开关、右侧搜索 / 排行榜 / 设置入口，
以及二级页自己的页头——搜索行、榜单标题行、集合页标题行）整体收起；回到列表顶部、或焦点回到页头里的
任何控件时再展开。此前页头一直占着屏幕最上面一条，向下翻列表时它和列表内容挤在一起，观感很乱。

三条必须同时成立的观感（排行榜 / 搜索 / 首页一致）：

1. **滚到中间时列表不会盖住页头那一排按钮**——裁剪由滚动容器的外壳提供（见上一节第 2 条），
   页头行与列表在同一个纵向容器里上下排列，列表不可能画到页头上面。
2. **向下滚页头收起**（200ms 高度动画），**中间向上滚不会半路把页头弹回来**；
   只有回到列表最上边（`y ≤ 12dp`）才展开，另外焦点落进页头里的控件时立刻展开。
3. **同一页原地追加（加载更多）时页头保持原来的收 / 展状态**：用户还在列表中间，
   追加一页不应该把页头弹回来。换标签 / 换分类这类换页仍然从展开态开始。

实现放在 `MainActivity` 的页头收展三件套（`registerTopAreaRow()` / `onListScroll()` / `setTopAreaHidden()`）：

| 决定 | 原因 |
| --- | --- |
| 收起用**高度动画**，不用 `translationY` | 收掉之后列表真的多占这一条高度：顶部不会留下一条空白，也不会出现「按钮浮在列表上面」的叠层 |
| 每行单独记展开高度（`topAreaHeights`）与还原用的 `LayoutParams.height`（`topAreaRestore`） | 工具条是固定高度（`TvStyle.TOOLBAR_HEIGHT` 88dp），其余页头是 `WRAP_CONTENT`，还原方式不一样 |
| 收起时把这一行的 `clipChildren` 打开、展开时立刻关掉 | 收起过程中子控件不能画到行外；展开时又要让焦点描边画得出来（见上一节） |
| 收展之后 200+120ms 内忽略滚动回调（`topAreaSettleUntil`） | 视口高度变化会让 `ScrollView` 回夹 `scrollY`，不设静默期会在底部来回抖 |
| 焦点变化时检查新焦点是否落在页头里（`addOnGlobalFocusChangeListener`） | 收起的页头高度是 0，焦点落进去必须先展开，否则焦点停在看不见的按钮上 |
| 恢复上次滚动位置的那一次滚动不计入（`restoringScroll` / `HomeScreen.restoring`） | 否则一进页面页头就闪一下 |
| 展开只在「回到最上边」或「焦点进页头」时触发（`onListScroll()` 里没有「向上滚就展开」分支） | 列表中间向上滚时页头反复弹出 / 收起会把画面抖得很乱 |
| 「加载更多」这一次重建保留页头状态（`keepTopAreaState`），新登记的行按收起状态立刻摆好（`expandedHeightOf()` 先量基准高度） | 追加是同一页的原地重建，用户还在列表中间；不保留就会每追加一页弹一次页头 |
| 重建期把 `topAreaSettleUntil` 往后推 200+120ms（`catalogGrid()` 开头） | 重建自己会产生三次滚动（位置恢复、焦点回带、内容夹取），它们不是用户滚动，不能被当成「滚回顶部了」 |
| 位置恢复挂在列表的 `OnLayoutChangeListener` 上（`list.addOnLayoutChangeListener`），量完再用真实坐标 `scrollTo` | 内容还没测量时 `ScrollView.scrollTo` 的 `clamp` 里 `my >= child` 直接返回 0：在 `post` 里恢复等于把列表拉回顶部，页头跟着展开 |
| `TvStyle.animate=false` 的设备直接到位 | 低配电视不排队动画，只保留结果 |

首页剧架的滚动通过 `HomeScreen.onScroll` 上报，二级页各自的 `ScrollView` 直接挂监听，
两处走的是同一个 `onListScroll()`，因此首页和二级页的行为一致。

### 收展动画表必须先快照再取消（2026-10-06 修崩溃）

页头收展的动画放在 `topAreaAnimators`（`View → ValueAnimator`）里。原先页面重建时写的是
`topAreaAnimators.values.forEach { it.cancel() }`，这条边遍历边删的写法会抛
`ConcurrentModificationException`：

- `ValueAnimator.cancel()` 会**同步**回调 `onAnimationEnd`；
- 那条回调里 `topAreaAnimators.remove(row)` 正好从正在遍历的这张表里摘掉自己；
- `LinkedHashMap` 的迭代器在第二次 `next()` 时发现 `modCount` 变了，于是抛异常。

**页头只有一行时（首页工具条）不会崩**：唯一那项被删掉之后 `next` 已经是 `null`，
迭代自然结束、不会再校验一次 `modCount`。**两行以上（搜索行 / 榜单标题行 / 集合页标题行）必崩**，
而收展动画的那 200ms 里「展示更多 ↓」「刷新榜单」、切分类、进详情、返回列表都会走
`releaseCatalogViews()` 重建页面——表现出来就是「下拉加载更多时偶发崩溃」。

修法：先把运行中的动画快照成列表、清空表、再逐个 `cancel()`；同时把结束回调里的
「先判等再删」改成原子的 `topAreaAnimators.remove(row) === this@apply`。
`tools/verify-button-system.py` 第 11 条按这个规则核对（反向注入旧写法时脚本必须失败）。

### 加载更多之后页头又展开（2026-10-06 修）

「下拉加载更多」之后顶部那排按钮又冒出来，有三条独立原因，都要堵：

1. **列表中间向上滚就展开**：旧 `onListScroll()` 里有一条 `y < listScrollY - 4 → 展开`，
   追加一页后回头看新内容（向上滚）就会把页头弹回来。这条分支已按需求删掉，
   只有回到最上边（`y ≤ 12dp`）或焦点进页头才展开。
2. **重建期自己产生的滚动被当成用户滚动**：列表重建会连带产生三次滚动——位置恢复、
   焦点回带（把新卡片带回可见区域）、内容高度变化后的夹取。它们会走到 `onListScroll()`，
   其中「位置恢复」那一次尤其危险：内容还没测量时 `ScrollView.scrollTo()` 的 `clamp()`
   里 `my >= child` 直接 `return 0`，于是列表被拉回顶部，页头判定「滚到最上边了」并展开。
   现在 `catalogGrid()` 开头把 `topAreaSettleUntil` 往后推 200+120ms，并且把位置恢复
   挂到列表的 `OnLayoutChangeListener` 上（量完再用真实坐标 `scrollTo`）。
3. **离树控件当焦点目标**：页头行与底部按钮都是新建的，如果 `moreButton` / `moreFocus`
   还留着上一页的引用，焦点请求会落到已经离树的控件上并失败，焦点就可能被系统交回
   页头里的第一个可聚焦控件，页头于是被重新展开。现在这两者在 `catalogGrid()` 开头就清空。
